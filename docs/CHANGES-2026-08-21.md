## 2. SEO — the main body of work

### 2.1 Two levels of override

Nothing about SEO was editable before; every title and description came from
code. There are now two layers, both optional and both falling back to the old
behaviour when blank:

- **Static pages** — `/`, `/products`, `/protection`, `/about`, `/contact`.
  Stored one row per path in the new `page_seo` table, edited at `/admin/seo`.
  The editable set is declared in `src/lib/seo.ts` as `SEO_PAGES`.
- **Products** — each product carries its own `seo_title` and `seo_description`,
  edited on the existing product form.

The fallback chain for a product page is now:

```
seoTitle       || "<name> — <hp ranges>"
seoDescription || tagline || first 160 chars of description
```

So an empty field changes nothing, which is why an un-migrated database still
renders correct pages.

### 2.2 New files

| File | Role |
|---|---|
| `src/lib/db/pageSeo.ts` | The only module touching `page_seo`. Reads degrade to "no override" when the DB or table is absent; **writes deliberately do not swallow errors**, so a failed save is visible in the admin. |
| `src/app/admin/seo/page.tsx` | The editor route |
| `src/app/admin/seo/SeoForm.tsx` | The form |
| `docs/SEO.md` | His own write-up: implementation, admin usage, JSON-LD, operator guidance, indexing timeline |

### 2.3 Wider metadata

`src/lib/seo.ts` changed shape: `pageMetadata` used to omit the `images` key
entirely when a page passed none. It now always resolves to
`site.ogImage` as a default, so **every** page emits an OG image instead of
only those that supply one. JSON-LD gained `logo` and `image` pointing at
`site.logo`. `/contact` was added to the sitemap at priority 0.7.

### 2.4 `site.ts`

```diff
+ logo:    "https://vkon.in/brand/vkon-logo-round.jpeg"
+ ogImage: "https://vkon.in/brand/vkon-og-banner.jpeg"
- description: "Vkon builds electronic motor starters and control panels for agricultural pumps — …"
+ description: "Advanced motor starters, industrial panels, and smart home automation with robust built-in protection and mobile control."
```

Note both new URLs are **hard-coded to `https://vkon.in`**, while `url`
directly above them is env-overridable (`SITE_URL`) precisely so staging does
not advertise production. A staging deploy will therefore point its OG image
and logo at production. Harmless today; worth knowing before a staging
environment exists.

## 3. Database — read this part

### 3.1 What was added

```sql
ALTER TABLE products ADD COLUMN IF NOT EXISTS seo_title       TEXT NOT NULL DEFAULT '';
ALTER TABLE products ADD COLUMN IF NOT EXISTS seo_description TEXT NOT NULL DEFAULT '';

CREATE TABLE IF NOT EXISTS page_seo (
  path        TEXT PRIMARY KEY,
  title       TEXT NOT NULL DEFAULT '',
  description TEXT NOT NULL DEFAULT '',
  updated_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

Everything stays `IF NOT EXISTS`, nothing drops or rewrites, so `schema.sql`
remains safe to re-run.

### 3.2 Migrations are now automatic on the server

This is the single most important operational change, and it **supersedes
HANDOFF §6**, which still says to run `npm run db:setup` on the server by hand.

He added a `db-setup` service to `docker-compose.yml`:

```yaml
db-setup:
  image: postgres:16-alpine
  depends_on:
    db: { condition: service_healthy }
  volumes:
    - ./src/lib/db/schema.sql:/schema.sql:ro
  command: psql -h db -U vkon -d vkon -v ON_ERROR_STOP=1 -f /schema.sql
```

It mounts `schema.sql` and applies it every time the stack starts. A schema
change now ships with its own migration; there is no manual step on deploy.

### 3.3 The local trap this creates

Local development has **no such automation**. Pulling these commits gave a
working tree whose code expects columns and a table the local database did not
have, and the failure is quiet rather than loud:

```
[db] page_seo read failed: relation "page_seo" does not exist          (42P01)
[db] product query failed: column "seo_title" does not exist            (42703)
```

Pages still returned **200**, because every public read goes through
`safeQuery`, which returns `[]` rather than throwing — the same fail-soft
behaviour ARCHITECTURE §9 relies on when it says health checks must probe
`/api/health` and never `/`. The site looked fine and simply had no products.

Fix, already applied locally on 2026-08-21:

```bash
docker exec -i vkon-pg psql -v ON_ERROR_STOP=1 -U postgres -d vkon < src/lib/db/schema.sql
```

**Expect to need this after any pull that touches `schema.sql`.**

## 4. New interface work

| Component | What it does |
|---|---|
| `layout/IntroSplash` | Brand intro on a fresh visit. The logo flips in at centre, then flies to the header and lands on the real one. The header logo carries `data-brand-logo`; the splash measures that box live and transitions to match, so the landing is pixel-accurate at any breakpoint rather than a guessed corner. |
| `home/FeaturedProducts` | A centre-snapping horizontal row. Snap is `center`, not `start`, because the centred card is the one that reads as "picked up". A plain mouse wheel's vertical delta pages the row; a trackpad's horizontal delta is left alone so native momentum still works. |
| `about/TiltCard` | Cards that tilt toward the pointer. The whole effect is two CSS variables (`--rx`, `--ry`) consumed by a `.tilt` utility in `globals.css` — React computes only the two angles. Desktop pointers only, gated on `(hover: hover) and (pointer: fine)`. |
| `admin/products/ProductReorder` | Drag to reorder the product list, with up/down buttons for anyone without a mouse. Optimistic: the drop reorders immediately and fires the action in a transition. `sort_order` is no longer a hand-typed field. |

`globals.css` gained ~95 lines (the tilt utility and pop/animation helpers) and
`icons/ui.tsx` ~90 (new icons).

## 5. Where his work met mine

Worth flagging because it is easy to miss in a 34-commit pull.

**`RecentlyViewed` gained a pop effect** (+90 lines). Exactly one card is
popped at a time, and only while the section itself is in the viewport — an
`IntersectionObserver` gates it, and whichever card's centre sits nearest the
track's centre is the one popped. Hover only counts on a device that genuinely
has one, or a touch tap's stray `mouseenter` would stick the highlight on
whatever was first touched. The pop transform lives on an inner `<div>`, not
the hover-target `<li>`, so lifting the card never pulls it out from under the
pointer and loops. My arrows, widths and card sizing survived unchanged.

**He fixed a real bug in my spec list.** The `whitespace-nowrap` I had removed
when the atomic-wrap rule was dropped turned out to still be load-bearing:
without it a multi-word value like "Direct on line (DOL)" breaks mid-phrase,
which looks wrong *and* leaves the flex-wrapped line short of the card's right
edge instead of moving the whole value down. He restored it alongside the
`opacity-0` truncation logic. Both comments are now merged in the file.

He also added `translate` to the transition property list on both card
orientations, so the pop's lift is animated rather than snapping.

**Untouched:** the hero and masthead scrims, the two-row catalogue, the
truncation-mark measurement.

## 6. `853d7c8` — the commit on top

One file: `public/brand/vkon-og-banner.jpeg`, replaced in place at the size the
brief specified, **1200 × 630**, keeping the filename so `site.ogImage` keeps
resolving.

The source was a 1254 × 1254 render of the badge on a *textured* grey wall —
corners sample 52–85, not a single colour. That ruled out the two obvious
fits:

- **Cropping** to 1.905:1 would have cut roughly 24 % off the badge, top and
  bottom.
- **Blur-extending** the background failed badly on inspection: the backdrop is
  a cover-crop of the same image, and its dominant feature is a large white
  circle, so the blur smeared into bright blobs either side with a dark square
  frame around the sharp centre.

What shipped is **edge-extension** — the badge scaled to the full banner height
and centred, with the source's own left and right edge columns stretched
outward to fill. Because the pad begins on the exact pixels the badge's edge
ends on, the join is continuous and the wall keeps its vertical vignette.

## 7. What is expected of you now

1. **Local database is migrated** — done 2026-08-21. Re-run the command in §3.3
   after any future pull that touches `schema.sql`.
2. **Nothing to run on the server.** Migrations are automatic now (§3.2).
   Confirm with him that the stack has actually restarted since, though — the
   service only runs on start.
3. **Re-scrape the OG image after deploy.** Facebook, LinkedIn and WhatsApp
   cache these hard, often for days. Use the Facebook Sharing Debugger and
   LinkedIn Post Inspector, or the old banner will keep appearing and look like
   the swap never happened.
4. **`allowedDevOrigins`** — the dev server warns about cross-origin requests
   from `172.20.10.5`. Only matters if you want to test from a phone on the same
   network; it needs that host adding to `next.config`.
